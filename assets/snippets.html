Big picture

The storefront calls the API through the gateway; the API reads PostgreSQL and asks the payment adapter to capture.

Source: src/server.ts, infra/gateway.conf

Step by step

One checkout request, in the order the code runs it. The diagram walks through the steps below on its own.

  1. Request — the storefront posts the cart (src/routes/checkout.ts:post).
  2. Validate — the body is checked against the cart schema (src/schemas/cart.ts:validate); 400 on failure.
  3. Reserve stock — one transaction (src/stock.ts:reserve).
  4. Capture payment — through the adapter (src/payments/index.ts:capture); mock by default.
  5. Provider answer — the mock adapter returns success at once.
  6. Response — the order id goes back to the storefront (src/routes/checkout.ts:post).

Source: src/routes/checkout.ts, src/payments/index.ts
