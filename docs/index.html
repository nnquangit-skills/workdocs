workdocs

Overview

A skill that makes your agent write six documentation pages from the code, with every claim traced to a file and nothing fetched at read time.

What it is

workdocs is an Agent Skill, a folder with a SKILL.md that an agent such as Claude Code loads when you say workdocs. It makes the agent write six reader-facing pages about your project from the project's own files: Overview, Setup, How it works, Security, API and Demo script. Every claim on those pages comes from a file the agent read, each section names those files, and anything mocked, simulated or planned is labelled as such.

The pages are plain static HTML in docs/. They open from a folder, fetch nothing, and stay readable with JavaScript off. You can keep them in the repository and hand them to anyone.

The rules in SKILL.md are instructions to the agent, not code that enforces them. An agent that ignores them can still write a page. The checklist in references/qa.md is how you tell: the report has to say which checks ran.

Architecture

  • The skill: SKILL.md (hard rules, the run, the work-map rule) and references/ (what each page must contain, what "static" means, optional helpers, the QA checklist). The agent loads these when you say workdocs.
  • The assets: assets/page.html (page skeleton), workdocs.css (one look, light and dark), workdocs.js (theme toggle, copy buttons, the self-running animations) and snippets.html (the flow, the step player, the Work map card, the video block). Copied into docs/assets/ once; never fetched.
  • The output: six HTML files in docs/ with the content embedded, each section between workdocs:begin / workdocs:end markers and a line naming its sources.

Quick start

git clone git@github.com:nnquangit-skills/workdocs.git ~/.claude/skills/workdocs
cd /path/to/your/project
claude                      # or any agent that supports Agent Skills
> workdocs                  # the agent reads the project and writes docs/

Open docs/index.html when the agent reports. Everything else is on Setup.
