workdocs

Demo script

A three-minute demo: one word, six pages, every claim traced, then a hand edit that survives the next run.

Goal and audience

Show, in about three minutes, that one word in the chat gives a project six documentation pages whose every claim points at a file, and that the pages are plain files anyone can open. Audience: developers who run coding agents and leads who are tired of stale docs. Everything in the demo runs for real on a local project.

Source: SKILL.md intro, README.md

Prerequisites

  • Claude Code (or another agent that supports Agent Skills) with workdocs installed in ~/.claude/skills/workdocs.
  • A small project with a README, a manifest and a few source files; a copy you do not mind writing into. Not a client repository.
  • A terminal and a browser side by side, about 1400 px wide; no private tabs, no keys on screen.
  • No accounts and no network needed beyond the agent itself.

Source: README.md "Install", SKILL.md compatibility line

Setup commands

git clone git@github.com:nnquangit-skills/workdocs.git ~/.claude/skills/workdocs   # once
cp -R /path/to/small-project /tmp/docs-demo && cd /tmp/docs-demo
rm -rf docs && ls                       # start without a docs folder
claude

Ready when the agent prompt is up and ls shows no docs/.

Script

Lanes: what the presenter says, what is typed in the chat or terminal, what the audience sees in the browser. The diagram walks through the steps below on its own.

  1. Open — say: "Docs go stale because someone has to write them after the work. Let's give that job to the agent, with one rule: no claim without a file." Show the project tree without docs/.
  2. Trigger — type workdocs. Say: "One word. The skill tells the agent what to read and what each page must contain."
  3. Watch it read — point at the files the agent opens: README, the manifest, entry points, tests. Say: "Nothing from memory. If it did not read it, it cannot write it."
  4. Watch it write — six files appear in docs/ plus assets/. Expected: the agent's report lists created pages, evidence gaps, checks run and the workmap status.
  5. Open the Overview — open docs/index.html from the file system. Expected: navigation with six entries, the Status table with real / mock tags, every section ending in a "Source:" line.
  6. How it works — click the nav entry. Expected: the flow is moving; scroll to Step by step and the sequence diagram walks the steps by itself. Say: "Nothing to click. It is documentation, you read it."
  7. Plain files — toggle dark with the ◐ button, then view the page source. Expected: the content is in the HTML, between workdocs:begin and workdocs:end markers; no fetch anywhere.
  8. Keep your edits — add data-workdocs="keep" to one section, change its text, then say "refresh the docs". Expected: that section is untouched, the rest regenerated, the old files backed up under docs/.workdocs-backup/.
  9. Close — say: "Six pages, every claim traced, nothing fetched, and it pairs with workmap when you want the map of what the project is doing." Show the Work map card on the Overview.

Fallbacks

  • The agent does not load the skill: type /workdocs, or check the folder is in ~/.claude/skills/.
  • The run takes longer than the slot: keep a finished docs/ from a rehearsal in a sibling folder and open that; say so.
  • The flow does not move: the machine has reduced motion on; the pages are meant to stop then. Show the step list instead.
  • No browser: show docs/index.html in the terminal with sed -n '1,60p': markers and sources are visible in the source.
  • Running out of time: skip steps 7 and 8.

Cleanup

rm -rf /tmp/docs-demo

No process was started; close the browser tab that shows file:///tmp/docs-demo/docs/.
