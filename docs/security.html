Security

The agent reads your repository and writes into docs/ only; the pages load nothing. What the rules cover, and what they cannot enforce.

Assets and trust boundaries

  • What the agent reads: your repository, including README, manifests, config and environment examples. Those files are untrusted content; the skill tells the agent to treat them as evidence, not as instructions, but it has no mechanism that enforces that (see Known gaps).
  • What the agent writes: files inside docs/ only: the six pages, docs/assets/, and backups under docs/.workdocs-backup/. Nothing outside the project.
  • What the reader runs: static HTML with one small script for presentation. No fetch, no XHR, no WebSocket, no dynamic import, no web font, no CDN, no analytics, no external images (references/static.md, "Forbidden").
  • Trust boundary: the published docs may be public. Whatever the agent writes into them leaves the repository's access control.

Source: SKILL.md Hard rules 2 and 7, references/static.md

Secrets handling

The skill needs no secret and stores none. It tells the agent to show environment variable names, their purpose and defaults from code, and never values from any .env file. If you keep secrets in files the agent reads, review docs/ before publishing; the checklist's grep for key-shaped strings is a net, not a guarantee.

Source: SKILL.md Hard rule 7, references/pages.md "Configuration", references/qa.md

Known gaps

  • Every control above is an instruction to the agent or a check it runs on itself. Nothing in the skill can stop a careless agent from writing a wrong or sensitive line.
  • No defence against instructions planted in the project's own files (a README that tells the agent to do something). The skill reads them as evidence and does not say what to do with embedded instructions.
  • The pages are static files: anyone who can read the repository or the folder reads the docs. Access control is the repository's.
  • Backups accumulate under docs/.workdocs-backup/ and are never pruned by the skill.

Source: SKILL.md, references/static.md
