workdocs

API

No endpoints and no CLI: a trigger word, and the markers, attributes, classes and tokens the written pages follow.

Interface type

workdocs has no HTTP API, no library and no command-line tool. Its public surface is a trigger (what you say to the agent) and a set of conventions in the pages it writes (markers, data attributes, CSS classes and tokens, one localStorage key) that you can rely on when you edit the pages or style them.

Errors

There is no runtime, so there are no runtime errors. At authoring time the failure modes are reported, not thrown: a claim with no evidence becomes "not stated"; a check that could not run is listed as unverified; a mismatch in docs/assets/ is reported and the existing files are kept; a page that does not apply says what is absent.
